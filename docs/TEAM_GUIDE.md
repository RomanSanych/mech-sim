# TEAM_GUIDE — как мы работаем (для инженеров, git знать не нужно)

Команда: **Роман** (архитектура, исправление ошибок), **Иван Борисович** (разработчик фич), **Матвей** и **Даня** (тестировщики).

**Главное правило:** все операции с git делает ИИ-агент. Вы ничего не вводите в терминале — говорите агенту по-русски, что нужно. Git — это «общая папка проекта» на GitHub, агент умеет с ней работать сам.

## Три слова, которые встретятся

- **Ветка** — ваша личная копия проекта, где можно ломать без последствий.
- **PR (пул-реквест)** — заявка «добавьте мои изменения в общий проект». Её открывает агент, живёт на сайте GitHub.
- **Мерж** — Роман на сайте нажимает кнопку, и изменения становятся общими.

## Роман — архитектура, исправление ошибок

- Ставит задачи: GitHub → Issues → New issue (шаблоны уже есть: «Фича», «Баг», «QA-проверка»). Задача = одна фраза + демо-сцена + критерий готовности.
- Ревьюит PR: открывает ссылку, смотрит список изменений, запускает демо у себя → кнопка **Merge**.
- Свои правки делает как разработчик: чат с агентом → ветка → PR.

## Иван Борисович — разработчик фич

**Первый день (один раз):** новый чат с агентом → стартовый промт из [`ONBOARDING.md`](ONBOARDING.md) §5.1. Агент сам скачает проект и создаст вашу ветку `dev-ivan`.

**Каждая задача:**

1. Новый чат → рабочий промт (`ONBOARDING.md` §5.2) + текст задачи из Issue.
2. Агент кодит, сам коммитит и пушит в вашу ветку. Вы следите за его отчётами.
3. «Открой демо» → смотрите сцену в Godot → говорите, что поправить, или «принято».
4. «Создай PR» → присылаете ссылку Роману. Всё.

## Матвей и Даня — тестировщики

Git-ветки не нужны вообще. Ваш цикл:

1. Роман или Иван дают задачу: «проверь фичу X, демо-сцена `res://test/...`» (обычно Issue с чек-листом).
2. Агенту: **«обнови проект до последней версии»** — он сам скачает свежее.
3. Открываете демо в Godot (Файл → Открыть), проходите чек-лист из задачи.
4. Всё работает → пишете в задачу «passed». Нашли баг → в приложении: **Помощь → «Сообщить об ошибке…»** — скриншот и сцена улетят в GitHub автоматически.

## Шпаргалка фраз для агента

- «Обнови проект» — скачать последнюю версию.
- «Создай ветку для задачи #N» — начать работу над задачей.
- «Открой демо» — показать результат в Godot.
- «Запушь и открой PR» — отправить на проверку Роману.
- «Скачай ветку PR #N» — посмотреть чужую работу до мержа.

**Если агент просит подтвердить что-то непонятное про git (push, force, reset) — стоп, спросите Романа.**

## Куда что писать

- Идеи по проекту → **Discussions** на GitHub.
- Баги → кнопка в приложении или Issue «Баг».
- Задачи → **Issues**. Ничего не храним в личных чатах и файлах вне проекта.
