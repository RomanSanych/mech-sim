# Репорт оркестратору — тепловизор / B3 (2026-10-22)

**Чат:** продолжение датчики B3 + тепловизор 3D  
**Исполнитель:** Auto (Composer)  
**Статус для оркестратора:** подэтап тепловизора — **в целом принято** пользователем; B3 УГО ТС — ждать отдельного «принято»; инцидент с затиранием файла — **критический урок / запрет для всех экзекуторов**.

---

## 1. Что сделано (кратко)

### Тепловизор 3D
- Покрытие: корпуса, жилы/трубки, щит (DIN, короба, дверца).
- Электро: `P = I²R` без педагогического потолка (КЗ → сотни/тысячи °C).
- Пневмо: доля `|Q|·|Δp|` + трение/`F·v` в тело; палитра ironbow.
- **Рентген + тепловизор:** tint на ghost `window` (как pressure_viz), не ломает полупрозрачность.
- **ПЦ по частям:** `barrel / piston / rod / cap / gland / shell` — разный нагрев и окраска; гильза умеренно; сальник/поршень горячее. Ответ пользователю: **~70 °C на всём корпусе — неадекватно**; локально у уплотнений — ок.
- Демо: `res://test/demo_thermal_viz.mechsim.json` (цикл ПЦ).

### КЗ в щите (тепловизор)
- Демо: `res://test/demo_thermal_short.mechsim.json` (QF1 → L–N, жила 0.5 мм²).
- Ток КЗ в нагрев жил (`electro_short` / `electro_fault_a`); детектор КЗ учитывает `supply_leg` (N/PE на других id).
- При тепловизоре короткая задержка выбивания АВ, чтобы вспышка была видна.
- УГО АВ: при срабатывании перерисовка Base (`scheme_control_epoch` / `bump_scheme_control`) — без «замкнутый+разомкнутый сразу».

### B3 Pt100 / ТСП
- MVP + правки; УГО правился в том же чате. **Не считать закрытым**, пока нет явного «принято» по УГО/3D зонда.

## 2. ИНЦИДЕНТ: полное затирание `symbol_geom.gd` (запретить повторять)

### Что случилось
В ходе правки УГО ТС исполнитель вызвал инструмент **`Write`** на файл:

`scripts/domain/symbol_geom.gd`

с **пустым `contents`** (фактически обнулил файл целиком — тысячи строк УГО всей схемы).

Мотив в момент ошибки: ускорить/заменить крупный кусок кода «целиком» вместо точечного `StrReplace`. Это **не** было запросом пользователя и **не** было осознанным удалением API.

### Почему это критично
- `symbol_geom.gd` — **ядро УГО** (цилиндры, клапаны, датчики, порты, сетка, теги…). Потеря = мгновенный простой всего 2D.
- Файл огромный; «переписать целиком из головы» после wipe **невозможно** без потери принятых этапов.
- Git в рабочей копии на момент инцидента **не дал** быстрый `checkout` (или файл уже был в «грязном» состоянии / восстановление шло из Cursor Local History).
- Восстановление: **Cursor Local History** (`User/History/.../symbol_geom`) + повторное нанесение незакоммиченных правок УГО ТС. Потеряно время пользователя и контекст чата.

### Как проявилось у пользователя
- Ошибки парсера / пропавшие символы на схеме.
- Запросы вида «восстанови», «auto_tag_offset», arity `begin_sch_layer_draw` — следствия пустого/частично восстановленного файла.

### Корневая причина (для политики)
1. Использование **`Write` как «стереть и написать заново»** для крупного существующего исходника.
2. Отсутствие жёсткого запрета на `Write` с пустым/почти пустым телом или на full-replace файлов >N строк без явного приказа.
3. Правка «всего УГО» в одном Write вместо серии `StrReplace` по известным якорям.

### ОБЯЗАТЕЛЬНЫЙ ЗАПРЕТ ДЛЯ ВСЕХ ЭКЗЕКУТОРОВ (внедрить в rules)

**Запрещено:**
- Вызывать `Write` / `write_file` на **существующий** исходник проекта с целью «переписать файл целиком», если файл уже > ~200 строк или это ядро (`symbol_geom.gd`, `circuit.gd`, `workshop_view.gd`, `schematic_view.gd`, `electrical_network.gd`, каталоги).
- Вызывать `Write` с **пустым** или заведомо урезанным содержимым на существующий файл (даже «на секунду»).
- «Чинить» синтаксис большого файла через обнуление + восстановление из памяти модели.

**Разрешено:**
- Только **`StrReplace` / точечный `edit_script`** по существующим файлам.
- `Write` — **только** для **нового** файла (демо JSON, новый мелкий модуль), либо если пользователь **явно** приказал «перепиши файл целиком» и есть git/бэкап.
- Перед любой массовой правкой УГО: skill `as-extract`, якоря в файле, маленький diff.

**Если файл всё же повреждён:**
1. Сразу стоп правок.
2. Восстановить: git → Local History → MCP undo cache — **не** регенерировать с нуля.
3. Сообщить пользователю одной фразой + путь восстановления.
4. Зафиксировать инцидент в `CURRENT.md`.

Правило-файл в репо: `.cursor/rules/no-full-file-wipe.mdc` (см. этот коммит/ход).
