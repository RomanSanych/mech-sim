## Электрика (утверждено)

- Питание / коммутация: **24 V DC** и **220 V AC** — оба с пилота/каркаса.
- Дискретные выходы: **контакт** / **NPN** / **PNP**; согласование с типом входа прибора (методичка).
- Аналог: **4–20 мА**, **0–10 В**, **0–1 В**, сопротивление ТС; общепром.
- ТС: схемы **2 / 3 / 4-провод**; **2-провод сразу с погрешностью** от R кабеля (как в методичке).
- **Активные** без питания → нет срабатывания / нет валидного аналога.
- **Пассивные** (геркон, сухой контакт) → срабатывают от условия без питания головки.
- Дискретные: **LED** состояния; аналоговые: **цифровой дисплей** (шрифт `D:\digitalcyrillic1.zip` → импорт в `res://`).

## Детекция целей (утверждено)

- Датчик реагирует на **любые подходящие объекты сцены**, не на отдельный «учебный таргет».
- Пример: корпуса ПЦ и прочих устройств из **металла** (сталь, алюминий и т.д.) — индуктивный БВ должен их видеть, если геометрия/зазор и материал подходят.
- В данных элементов (или мешей) нужна **маркировка материала / detect-свойств** (металл чёрный/цветной, диэлектрик, магнит, отражатель…), чтобы разные принципы (индуктивный / ёмкостный / оптика / геркон) фильтровали цели по физике, а не по `type == target`.
- Специализированные «учебные заготовки» допустимы как доп. объекты, но **не** как единственный способ срабатывания.

## Визуальный режим зон детекта (утверждён)

По аналогии с `circuit.pressure_viz` — отдельный флаг (напр. `sensor_field_viz`), **включается вместе с давлением** (не xor).

Суть UI/3D: не текстовые подписи в пространстве, а **визуализация форм коллайдеров/объёмов срабатывания** (и полей источников):

| Что | Как |
|-----|-----|
| Зона датчика | Полупрозрачный mesh = тот же объём, что коллайдер/запрос детекта (сфера/цилиндр Sn, конус, луч…) |
| Поле источника | То же для магнита, луча оптики, УЗ и т.п. |
| Состояние | Цвет/прозрачность: нет питания / норма / сработало — без обязательных лейблов в 3D |

- Физика hit-теста и видимый объём — один источник правды.
- Пилот A1: коллайдер Sn индуктивного. API полей — в каркасе; магниты — полноценно на A2.

## A4 оптика — принято (2026-10-21) · отчёт оркестратору

**Статус:** принято пользователем («в целом неплохо, двигаемся дальше»).

**Демо:** `res://test/demo_sensor_optical.mechsim.json`  
SQ1 fiber D · SQ2 barrier · SQ3 compact · SQ4 inductive · SQ5 capacitive.

### Сделано

**Исполнения / схема**
- `optical_form=fiber` (FD3-класс усилитель + tips) / `compact` (M18, только D/R, без OPT/волокна).
- Tips **не** на 2D; оптокабели **не** на схеме; тултипы оптики без P/Q; электро — V/I/R.
- Head: OPT1+OPT2 в один tip; tip Ø≈½; линза утоплена; барьер — луч только у TX.

**Уставки / UI 3D**
- Fiber-amp: PV/SET (DigitalCyrillic), кнопки +/− (±1 тик, hold с ускорением), SET teach, MODE LO/DO; **без** винта уставки.
- Compact / I / C: винт уставки (ось вала X + шлиц), hover-HL как у дросселя; LMB-up не «липнет».
- OUT = PV≥SET (Light-ON) / PV<SET (Dark-ON); default LO.

**Барьер / физика**
- Луч вдоль оси TX; RX в конусе + лицом навстречу; спад с дальностью (не рост).
- Crosstalk: PV = max(свой TX, чужие emitter/head, compact).
- Probe: `Main.agent_optical_probe(el_id)`.

**Кабель**
- Оптокабель: постоянный Ø; da/db родные портов; U-turn у tip ~180° без перелома (`_hose_curve_optic`).
- Отдельные gland на датчики.
