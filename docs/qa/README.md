# QA MechSim — памятка для инженера

Кратко: ты проверяешь **уже принятые** элементы и правишь баги вместе с **Codex**. Разработка новых фич идёт параллельно (тоже через PR в `main`).

## Репозиторий

- GitHub: https://github.com/RomanSanych/mech-sim (public)
- Godot **4** проект: корень репо (`project.godot`)

## Ветки (main-only)

| Ветка | Назначение |
|-------|------------|
| `main` | единственная рабочая линия; изменения только через PR |
| `bug-inbox` | вложения баг-репортов из приложения |
| tag `qa-baseline-2026-10-22` | ориентир: снимок, с которого стартовал первый проход QA |

Бывшие ветки `dev` и `qa/pass-1` удалены — работаем main-only.

### Как работать каждый день

1. Агенту: «обнови проект» (свежий `main`).
2. Один баг / один элемент → агент делает **свежую ветку от `main`**, например `qa/fix-inductive-led`, затем **PR в `main`**.
3. В том же PR обнови строку в [`STATUS.md`](STATUS.md). После мержа ветка удаляется.
4. Не начинай элементы со статусом «очередь / следующий» в handoff (B4+), пока Roman не попросил.

## Правила кода (обязательно)

- Читать [`AGENTS.md`](../../AGENTS.md) и `.cursor/rules/`.
- **Запрет wipe:** [`.cursor/rules/no-full-file-wipe.mdc`](../../.cursor/rules/no-full-file-wipe.mdc) — на ядра (`symbol_geom.gd`, `circuit.gd`, `workshop_view.gd`, …) только точечный `StrReplace`, никогда пустой/полный `Write`.
- Визуал: сделал → показал демо → жди фидбек; не крутить MCP-скриншоты в длинном цикле самооценки.
- Не трогать без запроса: автотрассу электро (`electro-autoroute`), незакрытый WIP эталон кабинета.

Файлы кладутся в ветку **`bug-inbox`** (`bug-reports/<stamp>/`), issue — в репозитории.

Нужен **GitHub CLI** на машине: `gh auth login` (права `repo`).  
Список: https://github.com/RomanSanych/mech-sim/issues
