# QA MechSim — памятка для инженера

Кратко: ты проверяешь **уже принятые** элементы и правишь баги вместе с **Codex**. Разработка новых фич идёт параллельно на другой ветке.

## Репозиторий

- GitHub: https://github.com/RomanSanych/mech-sim (public)
- Godot **4** проект: корень репо (`project.godot`)

## Ветки

| Ветка | Кто | Назначение |
|-------|-----|------------|
| `main` | интеграция | стабильная линия; изменения только через PR |
| `dev` | разработчик (Roman) | новые элементы (сейчас B4+), эксперименты |
| `qa/pass-1` | **ты + Codex** | проверка и фиксы уже сделанного |
| tag `qa-baseline-2026-10-22` | ориентир | снимок, с которого стартовал первый проход QA |

### Как работать каждый день

1. `git fetch` → checkout **`qa/pass-1`**.
2. Периодически подтягивай интеграцию:  
   `git merge origin/main` (или rebase — как договоритесь с Roman).  
   Так меньше конфликтов в конце.
3. Один баг / один элемент → **одна ветка** от `qa/pass-1`, например `qa/fix-inductive-led`, затем **PR в `main`** (не в `dev`).
4. После мержа PR: обнови строку в [`STATUS.md`](STATUS.md).
5. Не начинай элементы со статусом «очередь / следующий» в handoff (B4+), пока Roman не попросил.

## Правила кода (обязательно)

- Читать [`AGENTS.md`](../../AGENTS.md) и `.cursor/rules/`.
- **Запрет wipe:** [`.cursor/rules/no-full-file-wipe.mdc`](../../.cursor/rules/no-full-file-wipe.mdc) — на ядра (`symbol_geom.gd`, `circuit.gd`, `workshop_view.gd`, …) только точечный `StrReplace`, никогда пустой/полный `Write`.
- Визуал: сделал → показал демо → жди фидбек; не крутить MCP-скриншоты в длинном цикле самооценки.
- Не трогать без запроса: автотрассу электро (`electro-autoroute`), незакрытый WIP эталон кабинета.
